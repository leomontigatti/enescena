# Codebase map

Where code lives, and where a change usually goes. The map lists directories, not
every file: a file's own top comment and its tests say the rest. Update this page
when a directory is added, moved or given a new job.

## Layout

```
src/
├── routes/            TanStack Router file routes; `__root.tsx` is the document shell
│   └── api/auth/$.ts  Better Auth's HTTP handler
├── components/ui/     shadcn/ui components (see shadcn.md); add with the CLI, edit by hand
├── db/
│   ├── client.ts      the `db` client (lazy; `DATABASE_URL`)
│   ├── schema/        Drizzle schema in the `enescena` schema; `auth.ts` is generated, `index.ts` re-exports
│   └── migrations/    SQL migrations and drizzle's journal (`meta/`); generated, applied ones are frozen
├── lib/               shared helpers: `auth.ts` (server); `auth-client.ts` and `utils.ts` (`cn`) arrive with the first screen
├── server/            server-only modules that are not routes: `jobs.ts` (pg-boss)
├── router.tsx         the router factory; `routeTree.gen.ts` is generated and committed
├── routeTree.gen.ts   generated by the router CLI; never edited by hand
└── styles.css         Tailwind 4 and the theme tokens
scripts/               repo scripts and their unit tests (worktree DB, migrations, checks)
tests/db/              cross-cutting DB tests (see tests/db/README.md); their harness is src/test-support/database.ts
docs/adr/              decisions; docs/agents/ operative rules; docs/domain/ the model
```

## Where a change goes

- **A screen**: a route file in `src/routes/`, with its loader and action beside it
  when they are small. Shared presentational pieces go in `src/components/`.
- **A query or mutation**: a function beside its feature, called from a server function.
  Who may call it comes from the session, never from the request body.
- **A schema change**: edit `src/db/schema/`, run `pnpm db:generate`, and review the
  generated SQL. Migrations are never edited once applied.
- **A background job**: enqueue from the code path that knows the event, handle it in
  `src/server/`. Payloads sit in our own Postgres (ADR-0020); their contents are never logged.
- **A pure rule** (pricing, rounding, formatting, state transitions): a module in `src/lib/`
  or beside its feature, tested without a database or React.

## Tests

- `*.test.ts(x)` beside the code: unit tests (`pnpm test:unit`).
- `*.db.test.ts` beside the code, and `tests/db/**`: database tests on PGlite
  (`pnpm test:db`).
- Fixtures shared by one module's tests sit in `<name>.test-support.ts`; fixtures
  shared across modules sit in `src/test-support/` ([coding-standards.md](./coding-standards.md#test-support-files)).

## Ports from en-escena

The feature directories arrive with the ports (ADR-0020). The en-escena app organizes its code by
product surface (admin, portal, judging, vote, program) before resource; where each surface goes
here is decided with the first port and recorded on this page.
